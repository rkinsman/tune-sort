# TuneSort Mac App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A SwiftUI Mac app that does everything the `tune-sort` CLI does, driving the existing Python core through a `tune-sort serve` JSON-lines helper.

**Architecture:** Phase 1 adds small core hooks (cancel, per-song progress, cache listing and deletion, saving the order) and a `serve` protocol adapter in Python, which is usable and tested on its own. Phase 2 adds a Swift package: `TuneSortCore` (the helper client and `@Observable` view models, tested against fakes) and a thin `TuneSort` SwiftUI app target, bundled into `TuneSort.app` by a script.

**Tech Stack:** Python 3.12, uv, typer, pytest, ruff, mypy (strict); Swift 6, SwiftUI, Observation, XCTest, SwiftPM; Xcode for the SDK.

**Spec:** `docs/superpowers/specs/2026-10-29-mac-app-design.md`

  - New Python test files import helpers as `from tests.conftest import ...`.
- **Order in every task:** stubs first (signatures that raise `NotImplementedError` or `fatalError("unimplemented")`). Then the test writer's tests, run to confirm they fail for the right reason. Then the implementation.
- **Python checks before a task is done:** `uv run ruff check`, `uv run mypy src tests` and `uv run pytest -q`, all clean. Report the real output.
- **Swift checks before a task is done:** `swift build` and `swift test` in `mac/`, both clean.
- **Shell:** until a new session picks up `~/.zprofile`, prefix commands with `eval "$(/opt/homebrew/bin/brew shellenv)";`.
- **Git:**
  - Work on branch `mac-app`.
  - Ask the user once, at the start of execution, whether per-task commits are OK. They commit or push only when asked.
  - End commit messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Music:** only dry runs and scratch caches (`--cache` pointing at a copy) without the user's go-ahead.
- **Protocol:** `PROTOCOL_VERSION = 1`. JSON is one object per line, UTF-8, written with `ensure_ascii=False` and flushed after every line.
- **Errors:** error kinds are exactly `bad_request`, `busy`, `music`, `config`, `bad_tuning` and `internal`. `config` and `bad_tuning` messages use the same text as the CLI.
- **Platform:** the Swift package targets `.macOS(.v14)` (for Observation). Bundle id `com.rkinsman.TuneSort`.
- **Info.plist:** `NSAppleEventsUsageDescription` = "TuneSort controls Music to read your playlists and add songs to tuning playlists."
- **Defaults:** the repo path defaults to `~/code/tune-sort`, and the helper is `<repo>/.venv/bin/tune-sort serve`.
- **Sort confirmation copy:**
  - With a matching preview: `Add {n} song(s) to {p} playlist(s)` plus `, creating {c}` when c > 0, then `?`. Use the singular when the count is 1.
  - Otherwise: `Sort '{playlist}' into tuning playlists?`

## Review Focus

1. **Non-ASCII and punctuation in names** (Sigur Rós – Hoppípolla, AC/DC, quotes, en dashes) must round-trip unchanged through the cache, JSON and Swift. Tests are in Tasks 1, 5 and 8.
2. **A pipe chunk that splits a JSON line, or holds several lines,** must still decode as whole messages. Test in Task 8 (`LineSplitter`).
3. **A playlist that's empty, or was deleted after it was listed:**
   - Empty: `tracks` and `sort` return empty results.
   - Deleted: they return a `music` error, and the helper keeps running.
   - Tests in Tasks 4 and 6.
4. **A `cancel` that arrives after the sort finished,** or for an unknown id, gets `bad_request`. Neither the helper nor the app treats it as fatal. Tests in Tasks 6 and 9.
5. **Editing `config.toml` by hand into something invalid** while the app is open: `set_order` returns a `config` error, the file is left as it was, and Settings shows the message. Tests in Tasks 3 and 10.
